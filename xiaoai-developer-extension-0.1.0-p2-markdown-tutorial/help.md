# 小爱伴侣开发者教程

这是一份从安装到提交审核的完整教程。每一步都对应“**小爱伴侣-开发者工具**”当前界面中的按钮和字段。示例是本项目原创的最小示例，只演示接口形状，不包含任何第三方适配器源码。

> 交流QQ群：**849040712**。遇到页面差异或运行错误时，请附上学校、页面地址、错误详情和已完成的操作步骤，不要发送密码、Cookie、令牌或验证码。

## 1. 开始前：浏览器和插件

### 浏览器要求

- 使用 Chromium 系浏览器（Chrome、Edge 等）。
- Chrome 138 及以上：在扩展详情页打开“**允许使用用户脚本**”。
- Chrome 135–137：打开浏览器“**开发者模式**”。
- 允许侧栏访问当前教务页面；插件只会申请当前站点来源，不要求固定的“所有网站”权限。

### 安装插件

1. 解压测试包。
2. 打开浏览器的扩展管理页。
3. 打开“开发者模式”，点击“**加载已解压的扩展程序**”。
4. 选择解压后的插件目录。
5. 固定“小爱伴侣-开发者工具”图标，后续从工具栏打开侧栏。

开发调试时也可以直接加载仓库的 `apps/extension/dist`。生产构建得到的 ZIP 只用于分发，不要把 ZIP 当作源码目录编辑。

## 2. 登录开发者工具

插件采用 QQ 号加邮箱验证码登录，不读取 QQ 密码，也不要求 GitHub 登录。

1. 打开插件侧栏，看到“**登录开发者工具**”。
2. 在“**QQ 号**”输入 5–12 位数字，首位不能是 0。
3. 点击“**发送验证码**”。验证码会发送到该 QQ 号对应的 QQ 邮箱。
4. 输入“**6 位验证码**”，点击“**验证并登录**”。
5. 如果 QQ 号填错，点击“**更换 QQ 号**”；等待倒计时结束后可点“**重新发送**”。

登录后首页显示“**我的适配器**”。账号资料可从右上角“更多操作”中的“**同步 QQ 资料**”刷新。

## 3. 新建或选择适配器

首页只展示当前账号的适配器和平台记录。状态可能是“开发中、需要修改、审核中、审核通过、已上线、已替代、已下线”。

### 新建

1. 点击“**新建适配器**”。
2. 填写“**适配器名字**”，例如“某大学教务”。
3. 填写“**版本**”。版本是发布版本，不要因为一次校验失败就随意递增。
4. 选择“**小爱**”或“**拾光**”。
5. 在“**学校**”中搜索并选择学校。搜索框也支持输入未收录学校全称。
6. 填写“**教务地址**”。它是默认入口；实际运行时以当前浏览器页面为准。
7. 填写“**说明**”（选填），用于记录本次版本的变化。
8. 点击“**创建并开始编写**”。

### 选择和编辑

- 点击首页的适配器卡片可继续开发。
- 工作区顶部的“**编辑信息**”可以重新打开同一向导。
- “更多操作”提供“**导入项目、复制适配器、导出项目、删除适配器、切换主题、同步 QQ 资料、退出登录**”。
- 改学校、教务地址、类型、版本或源码后，之前的测试核对会失效，需要重新运行。

## 4. 选择适配器类型

### 小爱

工作区的“源码”页有三个文件标签：

- `provider.js 获取页面`：在教务页面取得原始 HTML 或接口响应。
- `parser.js 解析课程`：把 Provider 结果转换成课程数组。
- `timer.js 读取时间`：返回学期和作息信息。

### 拾光

工作区只有一个 `script.js 运行脚本`。脚本直接在当前教务页面运行，通过拾光桥保存课程、作息和时间配置。

## 5. 小爱 Provider/Parser/Timer

小爱适配器的三个函数按“取页面 → 解析课程 → 读取时间”执行。函数名必须准确：

```js
// provider.js
function scheduleHtmlProvider() {
  return document.documentElement.outerHTML;
}
```

```js
// parser.js
function scheduleHtmlParser(html) {
  const text = String(html).match(/<title[^>]*>([\s\S]*?)<\/title>/i)?.[1] ?? "未命名课程";
  return {
    courseInfos: [{
      name: text.trim(),
      teacher: "",
      position: "待确认",
      day: 1,
      weeks: [1],
      sections: [{ section: 1 }]
    }]
  };
}
```

```js
// timer.js
async function scheduleTimer({ parserRes }) {
  return {
    totalWeek: 20,
    startSemester: "2026-08-31",
    startWithSunday: false,
    showWeekend: false,
    forenoon: 4,
    afternoon: 4,
    night: 0,
    sections: [{ section: 1, startTime: "08:00", endTime: "08:45" }]
  };
}
```

示例只用于理解返回结构。真实适配器应从页面读取课程、教师、教室、星期、周次和节次，不能把示例课程直接提交。

### Timer 的时间规则

- `startSemester` 是第 1 周开始日期，建议由页面读取；也可以让用户在 App 导入时设置。
- `totalWeek` 是总周数，缺省时运行器会给出提示并使用默认值。
- 适配器返回的 `sections` 应尽量包含真实节次的开始和结束时间。
- 不要把当前周数写死成课程周次；课程的 `weeks` 只表示该课程在哪些周上课。

### 小爱运行检查

点击“**运行**”前，插件会检查三个入口函数。缺少函数时会直接指出文件名，例如“`parser.js` 缺少 `scheduleHtmlParser` 函数”。运行过程中可点击同一个按钮“**停止**”。

## 6. 拾光 Bridge v1/v2

拾光 v1 使用 `AndroidBridge` / `AndroidBridgePromise`；v2 使用 `shiguangBridge` / `shiguangBridgePromise`。插件当前同时注入两组名称，而且四个名称引用同一套桥对象，完成状态、请求队列和错误处理共享。

建议新代码使用 v2 名称，旧适配器无需立即改写。

```js
// script.js：原创最小示例
(async () => {
  await shiguangBridgePromise.saveImportedCourses(JSON.stringify([{
    name: "示例课程",
    teacher: "示例教师",
    position: "A101",
    day: 1,
    weeks: [1, 2],
    startSection: 1,
    endSection: 2
  }]));
  await shiguangBridgePromise.savePresetTimeSlots(JSON.stringify([
    { number: 1, startTime: "08:00", endTime: "08:45" },
    { number: 2, startTime: "08:55", endTime: "09:40" }
  ]));
  await shiguangBridgePromise.saveCourseConfig(JSON.stringify({
    semesterStartDate: "2026-08-31",
    semesterTotalWeeks: 20,
    firstDayOfWeek: 1
  }));
  shiguangBridge.notifyTaskCompletion();
})();
```

可用能力包括：

- `shiguangBridge.showToast(message)`：显示短提示。
- `shiguangBridge.notifyTaskCompletion()`：声明脚本完成。
- `shiguangBridgePromise.showAlert(...)`、`showPrompt(...)`、`showConfirmDialog(...)`、`showSingleSelection(...)`：与用户交互。
- `saveImportedCourses(...)`、`savePresetTimeSlots(...)`、`saveCourseConfig(...)`：保存课程、作息和时间配置。

脚本必须最终调用 `notifyTaskCompletion()`，否则运行器会在 60 秒后显示超时。脚本抛出异常或页面发生未处理异常时，侧栏会结束运行并显示错误详情。

## 7. 来源、能力和提交描述

这些字段最终会进入提交描述（Submission Descriptor，指平台用来校验适配器的说明数据），并生成 Manifest（发布清单）。普通开发只需要关注它们的实际含义：

- **origins**：脚本实际访问的教务站点来源，例如 `https://jw.example.edu.cn/`。运行时会以当前页面来源为准补齐，不要填写无关站点。
- **capabilities**（脚本可使用的能力）：常见包括页面 DOM、同源 `fetch`、iframe、页面计时器、存储和混合内容。使用什么就声明什么；拾光脚本的页面请求会通过插件桥接到当前页面。
- **学校引用**：优先选择已有学校；未收录学校使用搜索框输入全称，插件会生成候选学校引用。
- **版本和说明**：版本是发布版本；“说明”会作为变更说明提交。
- **来源**：可填写项目来源 URL 和说明，留空表示没有额外来源。

插件会自动生成不需要开发者手填的字段，例如入口文件、系统类型、许可证、时区、最低 App 版本和方言分支。不要手工伪造发布 Manifest 或 GitHub 仓库信息。

一个适配器 ZIP 包含 `submission.json`、入口 JavaScript 和 `LICENSE`。平台收到后会校验文件与摘要，再生成 App 使用的发布包；插件不会等待仓库同步。

## 8. 在真实教务页测试

1. 先打开学校真实教务页面并完成登录。
2. 回到插件，点击源码页的“**打开教务**”申请当前站点权限；如果已经在正确页面，也可以直接运行。
3. 确认顶部显示的类型正确（“小爱适配器”或“拾光适配器”）。
4. 点击“**运行**”，观察短状态：运行中、已生成或运行失败。
5. 拾光页面有 iframe 时，等待页面区域加载完成再运行；页面上的当前课程结果优先于新建向导里填写的入口地址。
6. 点击“**测试**”查看只读课程表 JSON。核对页只展示运行结果，不会上传真实课表。
7. 确认课程名称、教师、教室、星期、周次、节次和时间都与真实课表一致，勾选“**与真实课表一致**”。

测试页可以打开“**课程表预览**”查看周视图；该预览只是本地结果，不会改变 App 正式课表。这里的 Schedule V2（统一课表 JSON 格式）只保留在当前侧栏会话中。

### 运行失败时先看哪里

侧栏下方的“**错误详情**”会保留错误堆栈；点击“**复制**”可以把完整详情交给维护者。不要只根据弹窗判断原因。

## 9. 8 位测试码：App 实机测试

浏览器核对通过后，在“测试”页的“**App 实机测试**”卡片生成 Canary（实机测试会话）。

1. 先完成“与真实课表一致”的勾选并提交当前 revision，平台记录存在后才能生成测试码。
2. 点击“**生成测试码**”。插件显示一个 `XXXX-XXXX` 格式的 8 位测试码。
3. 点击“**复制测试码**”，把测试码手动输入 Android App 的“设置 → 开发者工具 → 适配器测试”。
4. App 完成 Package 校验后进入教务页面；用户登录并主动点击读取，再确认只读课表预览。
5. 插件会轮询显示测试设备数量和 PASSED/FAILED 结果。
6. 测试结束后可点击“**关闭测试**”。

这里**没有二维码，也没有扫码入口**。测试码只用于当前 submission 的当前 revision，30 分钟后失效；它不是审核或发布门禁。

## 10. 提交、审核和 revision

提交流程固定为：

```text
运行脚本 → 核对课表 → App 实机测试 → 提交审核
```

1. 切换到“**提交**”标签。
2. 查看“确认适配器信息”和流程条。
3. 确认“提交审核”按钮已解锁后点击。
4. 看到“平台提交成功”表示平台已收到 ZIP；不代表已经上线或仓库已同步。

如果平台校验失败或审核要求修改，提交一个 revision（修订版本）：

- 保持同一个适配器 ID、版本和类型。
- 修改源码或说明后重新运行、核对和实机测试。
- 只有状态为“需要修改”时才会出现“**提交修改**”。
- 新 revision 不覆盖旧 revision；平台审核结果会重新从“提交”开始。

不要因为一次运行失败就递增版本。只有功能发布版本变化时才递增版本号。

## 11. 常见问题

### “当前页面不支持”

当前标签页可能是扩展页、设置页、文件页或其他非 HTTP 页面。打开真实教务页，再点击“**打开教务**”申请权限。

### 运行一直显示“运行中”

先等待页面和 iframe 加载；如果仍无结果，点击同一个“**停止**”按钮。检查脚本是否调用了拾光完成方法，或小爱 Provider 是否返回了值。

### 拾光提示没有调用桥能力

确认脚本使用 `shiguangBridge` / `shiguangBridgePromise` 或旧的 `AndroidBridge` / `AndroidBridgePromise`。至少调用一次桥能力，并在末尾调用 `notifyTaskCompletion()`。

### 小爱提示入口函数缺失

检查文件标签和函数名：`provider.js` 的 `scheduleHtmlProvider`、`parser.js` 的 `scheduleHtmlParser`、`timer.js` 的 `scheduleTimer`。

### 课表生成后有问题

进入“**测试**”查看“需要处理”列表。常见问题是课程重复、节次不完整、日期格式不正确或开学日期来源不明确。修复后必须重新运行，旧核对状态不会自动沿用。

### 没有获取到开学日期

开学日期不是必须由适配器提供；App 导入时可以由用户设置。若脚本返回日期，使用真实学期第一周日期，并确保它是周日或周一。

### App 测试码无法使用

检查测试码是否过期、是否仍绑定当前 revision，以及 App 是否联网。重新生成测试码不会改变 submission 状态。

### 提交按钮不可用

依次检查：运行成功、课表 JSON 已显示、“与真实课表一致”已勾选、App 实机测试已完成、没有未处理问题。切换源码、学校或配置后要重新走测试流程。

### 需要第三方工具源码吗？

不需要，也不要复制未获授权的第三方工具源码。插件提供的是兼容能力和标准课表结果；请只编写自己的页面读取、解析和时间转换逻辑。
